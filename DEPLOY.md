# Развёртывание Пульса

## Состав и статус

Отдельная npm-монорепа: `apps/api` (Node.js + PostgreSQL), `apps/frontend` (React), `packages/shared` (справочник анкеты), `web` (результат npm run build). Только `web` предназначена для статической публикации. База, отзывы, исходные отчёты и секреты туда не попадают. Исходный Excel-процесс проекта не изменён; переноса его истории в PostgreSQL пока нет. Реальная база при первом запуске пустая, демоданные не добавляются.

Это первый серверный вариант: анкета и общая сводка за историю и по неделям. Фильтры курсов, диапазон дат, графики и CSV прежнего сайта ещё не перенесены. Вход не требуется на обоих экранах. Публичного метода чтения индивидуальных ответов и отзывов нет.

Готовность поставки и выполненные проверки зафиксированы в `STATUS.md`. Dockerfile — воспроизводимый рецепт, он не заменяет требуемый tar. Архив готов только после успешного docker save.

## PostgreSQL

Нужен отдельный PostgreSQL 16+ или существующий сервер. Он не включён в образ приложения. Для локальной проверки (пароль замените):

```sh
docker network create dashmood
docker volume create dashmood-pgdata
docker run -d --name dashmood-db --network dashmood --restart unless-stopped \
  -e POSTGRES_DB=dashmood -e POSTGRES_USER=dashmood -e POSTGRES_PASSWORD=CHANGE_ME \
  -v dashmood-pgdata:/var/lib/postgresql/data postgres:16
```

У БД не требуется публичный порт. Том PostgreSQL 16: `/var/lib/postgresql/data`. В Dockrunner подключите к нему постоянное хранилище. Сначала запустите БД и дождитесь готовности. Приложение создаёт таблицу при старте; пользователь БД должен иметь CREATE в своей схеме. При недоступной БД старт завершится ошибкой — предусмотрите перезапуск контейнера. Секреты указывайте в панели Env, не в GitHub и не в статическом JS. Для удалённой БД используйте настройки TLS провайдера; проверку сертификата не отключать.

## Загрузка готового образа

Требуемый файл: `artifacts/dashmood-0.1.0-linux-amd64.tar` и SHA256 рядом с ним. Уточните архитектуру сервера: этот вариант для Linux amd64.

Архив создан и проверен 23.10.2026, размер 82 200 064 байта. Контрольная сумма и результаты проверок — в STATUS.md. На Linux перед загрузкой: `sha256sum -c dashmood-0.1.0-linux-amd64.tar.sha256`.

```sh
docker load -i dashmood-0.1.0-linux-amd64.tar
docker run -d --name dashmood-app --network dashmood --restart unless-stopped \
  -p 8080:8080 \
  -e DATABASE_URL=postgres://dashmood:CHANGE_ME@dashmood-db:5432/dashmood \
  dashmood:0.1.0
curl --fail http://localhost:8080/health
```

Ожидается HTTP 200 и `{"status":"ok"}` только при доступной БД. `/mood` — анкета, `/dash` — сводка. Внешний порт Dockrunner, например 3007, сопоставляется **внутреннему 8080**; тогда health — `http://SERVER:3007/health`. Приложение слушает `0.0.0.0`. Логи — stdout/stderr, файлового тома приложению не нужно.

| Переменная | Значение |
|---|---|
| DATABASE_URL | Обязательная строка подключения PostgreSQL; специальные символы пароля URL-кодируются |
| PORT | Внутренний порт, по умолчанию 8080 |
| API_BASE_URL | Публичный адрес API для браузера; пусто = тот же origin. Не адрес БД и не имя контейнера |
| ALLOWED_ORIGIN | При отдельном фронте точный origin фронта, например https://pulse.example.org, без завершающего /; иначе пусто |
| NODE_ENV | В образе уже production |

В Dockrunner понадобится адрес PostgreSQL, доступный **из контейнера приложения**. `localhost` там указывает на само приложение. Из приведённого описания сервиса не следует, что поддержан импорт `docker load`: уточните это у владельца Dockrunner. Если доступен только GitHub build, корнем отдельного репозитория должно быть содержимое `_ForDeploy` с Dockerfile. Не загружайте весь исходный DashMood с private/ и Отчеты/.

## Статический фронт и конфигурация после сборки

`npm ci && npm run build` создаёт `web/` внутри этой монорепы. Скопируйте содержимое `web` на статический сервер. Настройте `/mood` и `/dash` на выдачу `index.html` (SPA fallback); неизвестные `/api/*` не должны переписываться на HTML. Нужен корень домена, подкаталог пока не поддержан.

Единственный редактируемый конфиг: `web/runtime-config.js`:

```js
window.DASHMOOD_CONFIG = { API_BASE_URL: "https://api.example.org" };
```

Этот файл загружается до React и не входит в хешированный bundle. После правки сборка не нужна. Выдавайте его с Cache-Control: no-store. При раздаче фронта самим Node-контейнером `/runtime-config.js` формируется из `API_BASE_URL` при каждом запросе; конфигурация меняется через Env и перезапуск. При отдельном статическом сервере правьте или монтируйте файл в его document root. Env произвольного nginx сама по себе не меняет JS. Пароли в конфиг не помещать. Фронт и API должны иметь совместимые HTTP/HTTPS схемы.

## API

- GET `/health` — доступность приложения и БД, 200/503.
- GET `/api/form` — версия, три шкалы, 19 вариантов трудностей.
- POST `/api/responses` — `{course:1,scores:{emo:0,comfort:null,satisfaction:10},categories:["none"],feedback:""}`. Заголовки Content-Type: application/json и Idempotency-Key: UUID v4. 201 — сохранено, 200 — повтор того же запроса, 409 — ключ с другим содержимым, 400 — ошибка анкеты. Повтор запроса после сбоя должен сохранять ключ; после изменения содержимого нужен новый ключ.
- GET `/api/dashboard` — только общие и недельные агрегаты. Ноль — оценка, null — пропуск. Минимум 5 ответов и 5 оценок соответствующей шкалы. При скрытой неделе скрываются и показатели истории, чтобы не восстановить её вычитанием. При скрытой шкале она скрыта во всех недельных срезах и итоге. Это консервативное правило первого варианта.

`generatedAt` соответствует последнему сохранённому ответу, не времени открытия страницы. Время показывает Новосибирск; неделя — понедельник по этому часовому поясу. Уникальность запросов не означает уникальность студентов. Без авторизации нельзя гарантировать один ответ человека за неделю. Ограничение частоты и размера трафика настройте в reverse proxy Dockrunner; встроенной защиты от массовой накрутки пока нет. HTTPS должен завершаться на сервере перед приложением.

## Резервное копирование

Регулярно делайте закрытый pg_dump и проверяйте восстановление на отдельной БД. Volume не заменяет резервную копию. Дамп и том содержат индивидуальные ответы и отзывы; не публиковать. Образ приложения данных БД не содержит. При обновлении не удаляйте том.

## Воспроизводимая сборка архива

На Windows с работающим Docker Desktop (Linux containers): `powershell -File ./export-image.ps1`. Скрипт устанавливает зависимости из lockfile, запускает unit-тесты, собирает React и образ linux/amd64, проверяет его с отдельной тестовой PostgreSQL и выполняет `docker save -o artifacts/dashmood-0.1.0-linux-amd64.tar dashmood:0.1.0`. Создаёт SHA256 и проверяет docker load. Тест использует localhost:18080 и автоматически удаляет свои контейнеры, том и сеть; реальные базы не затрагиваются. Dockerfile оставлен для воспроизводимости. Сам tar передаётся отдельно, в Git он исключён.
